# 가상머니 모의투자 엔진 (paper_trader)

트레이더 전략이 매수 신호를 내면, 같은 조건으로 **1만 개의 가상 미래에서 미리 거래**해 보고
기대수익과 꼬리위험이 기준을 넘을 때만 가상 계좌로 매수합니다. 투자 비중도 시뮬레이션 결과(켈리 기준의 1/4)로 정합니다.

```
[전략] 매수 신호 (+8% 익절 / -4% 손절 / 20일)
   ↓
[시뮬레이터] 과거 250일 수익률을 섞어 1000개 경로 생성 (20%는 변동성 1.8배 급락장)
   ↓
[판정] 기대수익 ≥ 0.3% 그리고 최악 5% 평균손실 ≤ 12% → 승인, 비중 = 켈리 × 1/4 (최대 20%)
   ↓
[가상 계좌] 수수료·거래세·슬리피지 반영해 체결, paper_state.json 에 저장
```

**실제 주문 기능은 없습니다.** 토스증권 API는 시세 조회에만 씁니다. 실수로 돈이 나갈 수 없게 주문 코드를 아예 넣지 않았습니다.

## 설치

```bash
pip install -r requirements.txt
```

## 웹 화면으로 쓰기

```bash
python main.py
```

브라우저에서 http://localhost:8765/trader 를 엽니다. 스포츠 대시보드 왼쪽 메뉴의 "📈 모의투자"로도 들어갈 수 있습니다.

- **내 가상계좌**: 총자산·수익률·최대낙폭, 자산 그래프, 보유 종목, 체결 기록, "오늘 매매 실행" 버튼
- **백테스트**: 필터 사용 vs 전략 단독 vs 그냥 들고 있기를 그래프로 비교
- **시뮬레이션**: 종목과 익절/손절/보유일을 넣으면 수익률 분포와 승인 여부 표시
- **연결 설정**: 토스 키 설정 상태와 연결 확인

매매 실행·계좌 초기화는 이 PC(localhost)에서 접속했을 때만 됩니다. 초기화하면 이전 기록은 `paper_state.bak-날짜.json` 으로 남습니다.

## 판정 안정성

시뮬레이션은 무작위라서 경로가 1000개면 매수 신호 종목의 약 30%가 돌릴 때마다 승인/거절이 뒤집혔습니다(가상 데이터 측정).
그래서 경로를 1만 개로 늘리고, **기대수익에서 오차(표준오차×2)를 뺀 값**이 기준(0.5%)을 넘을 때만 승인합니다(뒤집힘 약 8%).
또 종목·날짜별로 시드를 고정해서, 같은 날 같은 종목은 스캔·상세·계좌 어디서 봐도 같은 결과가 나옵니다.
스캔과 가상계좌는 같은 기준(과거 상승률 50% 할인, 기대수익 0.5% 이상)을 씁니다.

## 가상계좌: 국내 전 종목 모드

"고를 종목"을 **국내 전 종목**으로 두면(기본값) 매일 실행할 때:
1. 보유 종목의 손절·익절·보유기간·추세 이탈을 점검해 팝니다.
2. 국내 전 종목을 스캔해 승인 종목을 점수 순으로 줄 세우고,
3. 최대 보유 종목 수(기본 10)·하루 신규 매수 수(기본 3) 안에서 위에서부터 삽니다.

명령줄: `python -m paper_trader run --universe` (감시 종목만: `--watchlist`). 같은 날 시세로 두 번 실행하면 막힙니다.

## 국내 전 종목 스캔

웹의 **국내 전 종목 스캔** 탭, 또는 명령줄:

```bash
python -m paper_trader scan
```

1. KRX 상장종목 목록에서 코스피·코스닥 보통주만 남깁니다 (해외·코넥스·우선주·스팩·관리종목·투자주의환기종목 제외).
2. 종목마다 약 1년치 일봉(네이버, 수정주가)을 받아 `cache/krx/` 에 저장합니다. 다음부터는 새로 생긴 날짜만 받습니다.
3. 상장 1년 미만, 20일 평균 거래대금 10억 원 미만은 뺍니다.
4. 전략 매수 신호가 난 종목만 시뮬레이션합니다.
5. 많이 돌릴수록 우연히 오른 종목이 위로 오기 쉬워서, 스캔에서는 과거 상승률을 절반만 믿고(`drift_shrink=0.5`), 기대수익 0.5% 이상만 승인하며, **점수 = 기대수익 / 최악 5% 평균손실** 순으로 정렬합니다.

이 방식이 실제로 통했는지는 과거 검증으로 확인하세요:

```bash
python -m paper_trader scan-check
```

과거 12개 시점에 그때까지의 데이터만으로 스캔하고, 뽑힌 종목을 같은 규칙으로 샀다면 어땠는지를 "아무거나 샀을 때"와 비교합니다.
지금 상장된 종목만 쓰므로 상장폐지 종목이 빠져 실제보다 좋게 나올 수 있습니다(생존 편향).

스캔 결과에서 "감시 추가"를 누르면 `watchlist.json` 에 저장되고, "오늘 매매 실행"은 감시 종목 + 보유 종목을 대상으로 합니다.

## 명령줄로 키 없이 먼저 해보기 (가상 주가)

```bash
python -m paper_trader backtest
```

"필터 사용"과 "필터 미사용(전략 단독)"을 같은 기간에 비교합니다. `--seed` 를 바꾸면 다른 가상 시장으로 테스트합니다.

```bash
python -m paper_trader mc --symbols A B C
```

종목마다 시뮬레이션 결과(승률, 기대수익, 하위 5%, 손절 비율)를 보여 줍니다.

## 무료 실제 시세 (키 불필요)

```bash
python -m paper_trader backtest --source yahoo --symbols 005930 000660 035420
```

국내 6자리 코드는 코스피(.KS)로 처리합니다. 코스닥은 `035720.KQ` 처럼 적으세요.

## 토스증권 시세로 매일 모의투자

1. `.env.example` 을 `.env` 로 복사하고 `TOSS_CLIENT_ID`, `TOSS_CLIENT_SECRET` 을 채웁니다.
2. 토스증권 Open API 설정에서 **이 프로그램을 돌릴 PC의 IP** 를 허용 목록에 등록합니다.
3. 연결과 응답 형식을 확인합니다. 토큰 값은 화면에 나오지 않습니다.

   ```bash
   python -m paper_trader toss-check --symbol 005930
   ```

   해석에 실패하면 출력된 원본 응답과 [공식 명세](https://openapi.tossinvest.com/openapi-docs/latest/openapi.json)를 보고 `.env` 의 `TOSS_CANDLES_PATH` 를 맞추세요. 필드명이 다르면 `toss_client.py` 의 `daily_closes()` 를 고치면 됩니다.
4. 장 마감 후 하루 한 번 실행합니다.

   ```bash
   python -m paper_trader run --source toss --symbols 005930 000660 035420
   ```

5. 계좌 현황을 봅니다.

   ```bash
   python -m paper_trader status
   ```

같은 날 두 번 실행하면 막힙니다(보유일 계산이 꼬이지 않도록). 다시 하려면 `--force` 를 붙이세요.

## 토스 API 주의사항

- 클라이언트당 토큰이 하나만 유효해, 새로 발급하면 이전 토큰이 끊긴다고 알려져 있습니다. 그래서 `.toss_token.json` 에 캐시해 재사용합니다. 같은 키를 다른 프로그램과 같이 쓰면 서로 끊을 수 있습니다.
- 엔드포인트 경로·토큰 요청 방식·응답 필드는 공개 자료끼리 다른 부분이 있어 **검증되지 않았습니다.** 401이 나면 `.env` 의 `TOSS_AUTH_STYLE=basic` 으로 바꿔 보세요.
- 비용 기본값(수수료 0.015%, 매도 거래세 0.20%, 슬리피지 0.05%)은 `portfolio.py` 의 `Costs` 에서 바꿀 수 있습니다. 거래세는 연도·시장마다 달라서 확인이 필요합니다.

## 전략 바꾸기

`strategy.py` 의 `TrendMomentumStrategy` 는 자리만 채운 단순 전략(이동평균 추세 + 모멘텀 + RSI)입니다.
`decide(symbol, closes, holding) -> Signal` 형태만 맞추면 LLM 트레이더 에이전트 등 어떤 전략이든 끼울 수 있고, 시뮬레이션 필터는 그대로 적용됩니다.

## 한계

- 시뮬레이션은 과거 수익률을 섞은 것이라 처음 보는 사건(급격한 금리 변화, 전쟁 등)은 반영하지 못합니다.
- 일봉 종가 기준이라 장중 손절은 표현하지 못하고, 갭 하락 시 손절선보다 더 잃습니다(실제와 비슷).
- 기준값(min_edge, max_tail_loss 등)을 백테스트 결과에 맞춰 자꾸 고치면 과최적화됩니다. 검증 기간을 따로 떼어 두세요.
- 과거·가상 성과는 미래 수익을 보장하지 않습니다. 실제 투자 판단과 책임은 본인에게 있습니다.
