# TeamHub — 사내 캘린더 & 업무지시 시스템

전 직원이 웹 브라우저(PC/모바일)로 접속해서 사용하는 사내 협업 프로그램입니다.

## 주요 기능

| 메뉴 | 기능 |
|---|---|
| 🏠 홈 | 오늘 일정, 내 할 일, 업무 현황(대기/진행/지연/완료), 내가 지시한 미완료 업무 수 |
| 📅 캘린더 | 월간 달력, 일정 등록/수정/삭제, 종일 일정, 색상, 공개 범위(전사/부서/나만), 업무 마감일 함께 표시 |
| 📋 업무 | 업무 지시(여러 명 동시 지시 가능), 우선순위·마감일, 상태 변경(대기/진행중/완료/보류), 코멘트, 받은/지시한/전체(관리자) 보관함, 검색 |
| 📊 매출분석 | (관리자) 거래명세서 기준 거래처별 납품금액 — 월별(올해 vs 전년) 꺾은선, 연도별 막대, 거래처×월/연 표, 전년 대비 증감, 공급가액/합계 기준 |
| 🚢 입고예정 | 품목·구매처·판매처·수량·예상입고일(ETA)·상태(발주/선적/통관/입고완료)·B/L·창고. 홈 화면에 오늘/이번 주/지연 입고, 캘린더에 🚢 표시 |
| 📄 거래명세서 | 견적서와 별도 메뉴. 공급받는자/공급자 2부 A4 인쇄·PDF, 이카운트 판매 전송 |
| 🧾 견적서 | 견적서 작성(품목·수량·단가 → 공급가액/세액/합계 자동 계산, 부가세 별도/포함/면세), 견적번호 자동 부여, **A4 인쇄·PDF 저장**(한글 금액·회사 도장 표시), 이전 거래처/품목 자동완성, 복사해서 새로 작성, 상태(작성중/발송/수주/실주) |
| 🔔 알림 | 업무를 받았을 때, 상태가 바뀌었을 때, 코멘트가 달렸을 때 알림 (30초마다 갱신) |
| 👥 직원관리 | (관리자) 직원 등록, 아이디/비밀번호 설정·변경, 부서/직급/권한/메일 수정, 퇴사 처리(비활성화) |
| 📧 Outlook 연동 | 업무 지시 메일 발송, **메일에서 바로 [진행 시작]/[완료 처리]**, 완료 시 지시자에게 메일, 매일 아침 마감/지연 리마인더, 업무별 메일 발송 기록 |

### 권한
- **직원**: 일정 등록, 본인 일정 수정/삭제, 업무 지시, 받은 업무 상태 변경·코멘트
- **지시자**: 본인이 지시한 업무 내용 수정·삭제
- **관리자**: 모든 일정/업무 관리, 전체 업무 조회, 직원 관리
- **아이디/비밀번호 설정·변경은 관리자만 가능**합니다. 직원은 본인 비밀번호를 직접 바꿀 수 없으며 관리자에게 요청합니다.

## 실행 방법

```bash
cd teamhub
pip install -r requirements.txt
python app.py
```

브라우저에서 `http://localhost:8100` 접속.
같은 사내 네트워크의 직원들은 `http://<서버PC의 IP>:8100` 으로 접속하면 됩니다.

### 최초 로그인
- 아이디: `admin`
- 비밀번호: `admin1234` (환경변수 `TEAMHUB_ADMIN_PASSWORD` 로 최초 생성 시 변경 가능)

**로그인 후 반드시 우측 상단 메뉴 → 비밀번호 변경을 해주세요.**
그 다음 👥 직원관리에서 직원별 아이디/비밀번호/Outlook 메일 주소를 설정해 전달하면 됩니다.

### 환경변수
| 변수 | 기본값 | 설명 |
|---|---|---|
| `PORT` | `8100` | 서버 포트 |
| `TEAMHUB_DB` | `teamhub/teamhub.db` | 데이터베이스 파일 경로 (이 파일만 백업하면 됨) |
| `TEAMHUB_ADMIN_PASSWORD` | `admin1234` | 최초 관리자 비밀번호 |

## ☁️ 24시간 운영 (클라우드 서버)

사무실 PC 대신 클라우드 서버(Vultr, AWS Lightsail, 네이버 클라우드 등)에 올리면 **24시간 운영 + 고정 IP**(이카운트 API 허용 IP 등록용)가 해결됩니다.

1. **서버 생성** (예: Vultr → Deploy → Cloud Compute → 지역 **Seoul**, OS **Ubuntu 24.04**, 가장 작은 사양(1 vCPU / 1GB)으로 충분)
2. **도메인 연결** — 도메인 관리(가비아 등)에서 `teamhub.우리회사.com` 의 **A 레코드**를 서버 IP로 설정
3. **설치** — 서버에 SSH 접속 후:
   ```bash
   git clone <이 저장소 주소> && cd <저장소>/teamhub
   sudo bash deploy/install.sh teamhub.우리회사.com
   ```
   - 도메인이 아직 없으면 `sudo bash deploy/install.sh ip` 로 IP 주소(HTTP)로 먼저 설치하고, 나중에 도메인으로 다시 실행하면 HTTPS 로 바뀝니다.
   - 자동 시작/재시작(systemd), HTTPS 인증서 자동 발급(Caddy), 방화벽, 매일 DB 백업(30일 보관), 한국 시간대가 설정됩니다.
   - 설치가 끝나면 **서버 공인 IP**가 표시됩니다 → 이카운트 API 허용 IP로 등록하세요.
4. **설정** — `sudo nano /etc/teamhub.env` 에 메일 설정 입력 → `sudo systemctl restart teamhub`
5. **업데이트** — `git pull && sudo bash deploy/update.sh` (업데이트 전 DB 자동 백업)

> 인터넷에 공개되므로 같은 아이디로 10분 안에 10번 로그인에 실패하면 10분간 잠깁니다.
> 백업 파일(`/var/backups/teamhub`)은 가끔 다른 곳(PC, 클라우드 드라이브)에도 복사해 두세요. Vultr 자동 백업 옵션(유료)을 켜두면 더 안전합니다.

## 🧾 견적서

1. (관리자) 🧾 견적서 → **🏢 회사 정보** 에서 상호·대표자·사업자번호·주소·업태/종목·전화, **도장 이미지**, 하단 문구를 등록합니다. (견적서의 공급자 칸에 표시)
2. **+ 새 견적서** → 거래처, 품목/수량/단가 입력 → 합계가 자동 계산됩니다. 한 번 입력한 거래처·품목은 다음부터 자동완성(단가·규격 자동 입력)됩니다.
3. **저장 후 인쇄** 또는 견적서 상세의 **🖨 인쇄 / PDF** → 인쇄 창에서 "PDF로 저장"을 고르면 PDF 파일로 받아 메일에 첨부할 수 있습니다.

**업무지시와 연결**: 업무 상세 화면의 **+ 이 업무로 견적서 작성** 으로 작성하면 견적서가 업무에 연결되고,
"저장하면서 업무 완료" 체크 시 업무가 자동 완료 + 지시자에게 알림/메일이 갑니다. (지시자는 업무 화면에서 견적서를 바로 확인)

## 📄 거래명세서

견적서와 **별도 메뉴(📄 거래명세서)** 로 관리합니다. 번호는 `T날짜-001` 형식.
- 공급받는자(거래처명·사업자번호·대표자·주소)와 품목·수량·단가 입력 → 공급가액/세액/합계 자동 계산
- **인쇄 / PDF**: 이카운트 거래명세서와 같은 양식 (거래처 貴中, 공급자 칸·도장, 금액 한글, 월/일·품명 및 규격·수량·단가·공급가액·부가세, 수량·공급가액·VAT·합계·인수 합계줄, 절취선). 품목 10개마다 한 장. 일련번호는 이카운트 판매 전표번호(전송 후) 또는 명세서번호
- 이카운트 연동 시 **이카운트 판매로 전송** (출고 창고 선택)
- 업무 상세에서 **+ 거래명세서 작성** 으로 업무와 연결 가능
- **지난 거래명세서 가져오기** (관리자): 이카운트는 판매 조회 API가 없으므로, 이카운트 **판매조회** 화면에서 [Excel]로 내려받은 파일을 📄 거래명세서 → **📥 이카운트에서 가져오기** 로 올립니다.
  미리보기 후 가져오며, 같은 일자-No. 전표는 다시 가져오지 않습니다.
- 이카운트 엑셀 날짜에 연도가 없으면(`11/16-1`) **조회기간을 1년 단위로** 내려받아 올리세요 (그 연도로 고정). 가져오기 창에서 연도를 직접 지정할 수도 있고, 잘못 가져왔으면 **가져온 문서 모두 지우기** 후 다시 올립니다.
- **지난 견적서**도 같은 방법: 이카운트 **견적서조회** 엑셀 → 🧾 견적서 → **📥 이카운트에서 가져오기** 가져온 명세서의 일련번호는 이카운트 전표번호 그대로 출력됩니다.

## 🔗 이카운트 ERP 연동

TeamHub 견적서를 이카운트 **견적서** 또는 **판매(거래명세서)** 로 바로 등록합니다.

**설정 (관리자)** — 🧾 견적서 → **🔗 이카운트**
1. 회사코드, 사용자 ID, **API 인증키** 입력, 서버 선택(**테스트 서버** = 테스트 인증키 / 실서비스 = 정식 인증키) → **연결 테스트**
   - 이카운트 API 인증키 발급 시 **허용 IP에 TeamHub 서버 공인 IP**를 등록해야 합니다.
2. **품목**: [이카운트에서 불러오기] (API로 전체 품목을 가져옴)
3. **거래처**: 이카운트 거래처등록 목록에서 Excel 로 내려받아 [엑셀 업로드] (이카운트가 거래처 조회 API를 제공하지 않음)
4. **창고**: `창고코드 창고이름` 을 한 줄에 하나씩 입력 후 저장 (또는 엑셀 업로드)

**사용**
- 견적서 작성 시 품목 칸에 **이름·코드·규격 일부만 입력**하면(여러 단어 가능, 예: `a4 500`) 이카운트 품목이 검색됩니다. 선택하면 품목코드가 연결되고 규격·단위·단가가 채워집니다.
- 거래처명 칸에서도 이카운트 거래처를 검색해 선택합니다. 띄어쓰기·(주)·주식회사는 무시하고, 여러 단어로 찾을 수 있습니다 (예: `삼성 2공장`). 거래처 엑셀에 주소 열이 있으면 검색 결과에 함께 표시되어 공장/지점을 구분할 수 있습니다.
- 견적서 상세 → **견적서로 전송** / **거래명세서(판매)로 전송** (판매는 **출고 창고 선택**) → 이카운트 전표번호가 기록됩니다. 판매 전송 시 견적서 상태는 '수주'로 바뀝니다.
- 같은 문서를 두 번 보내려 하면 경고합니다. 전송 기록은 🔗 이카운트 화면 하단에서 확인합니다.

> 견적서 입력 API 경로가 이카운트 매뉴얼과 다르면 🔗 이카운트 → 고급에서 바꿀 수 있습니다.

## 📧 Outlook 메일 연동

### 동작 방식
1. 업무를 지시하면 담당자의 Outlook으로 **[업무지시] 메일**이 갑니다. 메일 안의 **▶ 진행 시작 / ✔ 완료 처리** 버튼으로 TeamHub에 로그인하지 않고도 바로 상태를 바꿀 수 있습니다.
2. 담당자가 상태를 바꾸면(웹이든 메일이든) **지시자에게 [업무완료] 등의 메일**이 가서, 업무를 했는지 안 했는지 바로 확인할 수 있습니다.
3. 매일 아침(기본 9시) **담당자에게는 마감일이 오늘이거나 이미 지난 미완료 업무 리마인더**, **지시자에게는 기한이 지났는데 끝나지 않은 업무 요약**을 보냅니다.
4. 업무 상세 화면과 👥 직원관리 하단에서 메일 발송 기록(발송/실패/미설정)을 볼 수 있습니다.

> 메일의 버튼 링크는 업무·담당자별로 서명되어 위조할 수 없고, 링크를 열면 확인 화면이 먼저 나오므로 Outlook 보안 링크 검사(Safe Links)가 링크를 미리 열어도 상태가 바뀌지 않습니다.

### 설정 (Microsoft 365 — 권장: Graph API)
Microsoft는 Exchange Online에서 아이디/비밀번호 방식의 SMTP 발송(기본 인증)을 단계적으로 폐지하고 있으므로,
**Microsoft 365를 쓰는 회사는 아래 Graph API 방식**으로 설정하세요. (비밀번호 대신 회사 테넌트에 등록한 앱으로 발송)

**1) 발송용 메일함 준비**
- 예: `teamhub@회사도메인` (Microsoft 365 관리 센터에서 사용자 추가 또는 **공유 사서함**으로 만들면 라이선스 비용 없음)

**2) 앱 등록** — [Microsoft Entra 관리 센터](https://entra.microsoft.com) (전역 관리자 계정)
1. ID → 애플리케이션 → **앱 등록** → **새 등록** → 이름 `TeamHub`, "이 조직 디렉터리의 계정만" → 등록
2. 개요 화면의 **애플리케이션(클라이언트) ID**, **디렉터리(테넌트) ID** 를 메모
3. **API 사용 권한** → 권한 추가 → Microsoft Graph → **애플리케이션 권한** → `Mail.Send` 추가 → **"(회사명)에 대한 관리자 동의 허용"** 클릭
4. **인증서 및 비밀** → 새 클라이언트 암호 → 생성된 **값**을 메모 (화면을 벗어나면 다시 볼 수 없음, 만료일 전에 갱신 필요)

> 보안 권장: `Mail.Send` 애플리케이션 권한은 기본적으로 모든 메일함으로 발송할 수 있습니다.
> Exchange 관리자가 **애플리케이션 액세스 정책(RBAC for Applications)** 으로 발송 메일함 하나로 제한해 두세요.

**3) 서버 실행**
```bash
export TEAMHUB_MS_TENANT_ID="디렉터리(테넌트) ID"
export TEAMHUB_MS_CLIENT_ID="애플리케이션(클라이언트) ID"
export TEAMHUB_MS_CLIENT_SECRET="클라이언트 암호 값"
export TEAMHUB_MAIL_FROM="teamhub@company.com"          # 1)에서 만든 발송 메일함
export TEAMHUB_BASE_URL="http://192.168.0.10:8100"      # 직원들이 접속하는 주소 (메일 버튼 링크)
python app.py
```

**4) 확인** — 👥 직원관리 하단에 `연동됨 · Microsoft 365 Graph API` 가 보이면 **테스트 메일 보내기**로 확인합니다.

### 전체 환경변수
| 변수 | 기본값 | 설명 |
|---|---|---|
| `TEAMHUB_MS_TENANT_ID` / `TEAMHUB_MS_CLIENT_ID` / `TEAMHUB_MS_CLIENT_SECRET` | (없음) | Microsoft 365 Graph 발송 설정 (세 값 + `TEAMHUB_MAIL_FROM` 이 있으면 Graph 사용) |
| `TEAMHUB_MAIL_FROM` | SMTP 계정 | 보낸 사람(발송 메일함) 주소 |
| `TEAMHUB_BASE_URL` | `http://localhost:8100` | 메일 속 링크 주소 — **반드시 직원 PC에서 접속 가능한 주소로 설정** |
| `TEAMHUB_REMINDER_HOUR` | `9` | 리마인더 발송 시각(0~23시) |
| `TEAMHUB_SMTP_USER` / `TEAMHUB_SMTP_PASSWORD` | (없음) | (대안) Graph 대신 SMTP로 발송할 때. Google Workspace·네이버웍스 등 |
| `TEAMHUB_SMTP_HOST` / `TEAMHUB_SMTP_PORT` | `smtp.office365.com` / `587` | SMTP 서버 (STARTTLS) |

## 구성
- `app.py` — FastAPI 백엔드 + SQLite DB (별도 DB 서버 설치 불필요)
- `deploy/` — 클라우드 서버 설치/업데이트 스크립트 (systemd, Caddy HTTPS, 백업)
- `ecount.py` — 이카운트 Open API 클라이언트 (로그인, 품목 조회, 견적서/판매 입력)
- `mailer.py` — Outlook 메일 발송(Microsoft 365 Graph API / SMTP), 메일 버튼 서명, 일일 리마인더
- `static/index.html` — 프론트엔드 (단일 파일, 외부 라이브러리 없음)

> 회사 외부(인터넷)에서 접속하게 하려면 HTTPS(예: Nginx + 인증서) 뒤에 두고 운영하는 것을 권장합니다.
